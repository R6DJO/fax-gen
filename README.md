# tiff2wav — генератор факс-аудио (TIFF → WAV)

Однофайловая консольная утилита на C99: читает TIFF-изображение и пишет
монофонический 16-битный WAV 8 kHz с FM-модуляцией в формате, близком к
**WMO APT** (Automatic Picture Transmission, mode 1A) — формату морских
погодных карт и любительского КВ-факса.

> EN: single-file C99 CLI that turns a TIFF image into 8 kHz mono 16-bit WAV
> audio, FM-modulated in a WMO/APT-like amateur-radio facsimile format.
> MIT licensed, no dependencies except libtiff.

**Статус:** рабочая, но проверенная только офлайн: генерация и round-trip
декодирования измерены (см. [Тестирование](#тестирование)), приём реальным
КВ-приёмником не проверялся. Ошибки, найденные при проверке, исправлены —
подробности в [Что исправлено после проверки](#что-исправлено-после-проверки).

## Зависимости

| Пакет (Debian/Ubuntu) | Зачем |
|---|---|
| `libtiff-dev` | чтение TIFF |
| `build-essential` (`gcc`, `make`) | сборка |
| `libc`, `libm` | стандартные |

WAV пишется вручную (RIFF-заголовок 44 байта), `libsndfile`/`audiofile` не нужны.

## Сборка

```bash
make
```

## Использование

```bash
./tiff2wav [опции] <input.tiff> [output.wav]
```

Если `output.wav` не указан — создаётся `fax_output.wav`.

| Флаг | Описание | По умолчанию |
|------|----------|--------------|
| `-c, --carrier FREQ` | Частота несущей, Гц | 1900 |
| `-d, --deviation DEV` | Частотное отклонение, Гц | 400 |
| `-l, --lpm LPM` | Строк в минуту | 120 |
| `-p, --phasing N` | Количество фазировочных строк | 60 |
| `-s, --start FREQ` | Частота стартового тона, Гц | 300 |
| `-S, --stop FREQ` | Частота стопового тона, Гц | 450 |
| `-t, --threshold N` | Порог бинаризации (0–255) | 128 |
| `-i, --invert` | Инвертировать полярность изображения | — |
| `-H, --hamfax` | Пресет фазировки hamfax: 20 строк, белый с обоих концов строки, дополнительная белая строка, без хвоста | — |
| `-h, --help` | Справка | — |

### Примеры режимов

**Морской погодный факс (WMO, значения по умолчанию):**
```bash
./tiff2wav image.tiff output.wav          # carrier 1900 Гц, ±400 Гц, 120 LPM
```

**Меньше фазировки:**
```bash
./tiff2wav -p 20 image.tiff output.wav
```

**Фазировка как в hamfax:**
```bash
./tiff2wav --hamfax image.tiff output.wav
```

**Класс A (более узкая полоса):**
```bash
./tiff2wav -c 2400 -d 900 -l 200 -s 1370 -S 1610 image.tiff out.wav
```

## Структура сигнала

1. **APT start tone** — чередование чёрный/белый на `start_freq` Гц, 5 с.
2. **Phasing lines** — `N` строк синхронизации: 25 мс белый уровень + 475 мс чёрный.
3. **Данные изображения** — по одной строке TIFF на строку сигнала;
   чёрный → `carrier − deviation`, белый → `carrier + deviation`.
4. **APT stop tone** — чередование чёрный/белый на `stop_freq` Гц, 5 с.
5. **Black silence** — 10 с чёрного уровня (`carrier − deviation`).

С пресетом `--hamfax` пункты 2 и 5 меняются: 20 строк с белым уровнем по 2.5 %
на обоих концах каждой строки, одна дополнительная полностью белая строка и
отсутствие хвоста (как в hamfax).

Модуляция: фазовый аккумулятор 32 бита, синус вычисляется на каждом отсчёте
(`sin(2π·phase/2³²)`), частота выбирается из двух приращений (чёрный/белый).

## Тестирование

```bash
make test      # сборка + обе карты + пресет --hamfax: контейнер, поля `fmt `, длина WAV
```

В репозитории две собственные карты, воспроизводятся скриптом (нужен Pillow):

```bash
cd tests && python3 make_test_card.py
```

| Файл | Что проверяет |
|---|---|
| `tests/test_card.tiff` | 8 бит/пиксель: полосы + шкала серого |
| `tests/test_card_1bit.tiff` | 1 бит/пиксель (bilevel) — типичный вход факсовых TIFF |

Для каждой карты `make test` проверяет magic `RIFF`, поля `fmt ` (PCM, моно,
8000 Гц, 16 бит) и точную длину — 2 400 044 байта: 5 с стартового тона +
60 фазировочных строк + 200 строк изображения + 5 с стопового тона + 10 с
чёрного уровня при 120 строк/мин и 8 kHz. Третий прогон — пресет `--hamfax`
на 8-битной карте, ожидаемая длина 1 928 044 байта.

Отдельно (скриптом вне репозитория) измерялся round-trip: сгенерированный WAV
декодировался по нулевым пересечениям и сравнивался с исходным изображением.
Совпадение — **100 %** для обеих карт и **97.3 %** для погодной карты 1809×600
(остальное — искажения собственного декодера).

## Что исправлено после проверки

Измерено на этой машине (Ubuntu, libtiff 4.5.1, gcc -O2, valgrind 3.22),
а не «по ощущениям».

### 1. Порядок байт в WAV

Данные писались big-endian при заголовке RIFF, то есть обычный читатель
(ffmpeg, audacity, audiofile, воспроизведение через звуковую карту) читал
отсчёты перевёрнутыми. Теперь пишется little-endian, как требует RIFF/PCM.

| Метрика | до | после |
|---|---|---|
| round-trip, 8-битная карта | 43.0 % | 100.0 % |
| round-trip, погодная карта 1809×600 | 52.3 % | 97.3 % |
| частота нулевых пересечений в фазировочных строках | 4960 Гц | 3080 Гц (теория — 3080) |

Можно было оставить big-endian и объявить форму `RIFX`, но little-endian
совместим шире.

### 2. TIFF не-8-битной глубины (в том числе 1-битные bilevel)

Чтение построчно предполагало 8 бит на канал (и подставляло 8, если тега
`BitsPerSample` нет), поэтому bilevel-файлы читались из неинициализированной
части строкового буфера. Теперь изображение декодируется через
`TIFFReadRGBAImageOriented()`.

| Метрика (bilevel 600×200) | до | после |
|---|---|---|
| valgrind | 700000 использований неинициализированной памяти | 0 ошибок |
| round-trip | 44 % | 100 % |

Проверено на bilevel minisblack / miniswhite / LZW, 8-бит gray, 8-бит LZW,
16-бит gray, palette, RGB, RGBA: round-trip 100 % и 0 ошибок valgrind.

### 3. Нецелое число отсчётов на строку

Длина строки усекалась до целого, а размеры областей считались из дробного
значения — в конце строк оставались короткие вставки нетронутых нулей.
Теперь граница строки вычисляется как `round(k × отсчётов_на_строку)`.

| Метрика (`-l 110`, all-black карта) | до | после |
|---|---|---|
| дрейф начала фазировочных импульсов | макс 39, среднее −19.1 отсчёта | макс 3, среднее −0.2 (предел детектора) |
| прогоны из ≥2 нулей в области сигнала | 2 | 0 |
| `-l 120` (целое число отсчётов) | макс 1 отсчёт | макс 1 отсчёт, регрессии нет |

### 4. Разбор и проверка параметров

`atof()`/`atoi()` молча превращали `-c abc` в 0 Гц, а `-d 2000` при `-c 1900`
давал отрицательную «чёрную» частоту (завёрнутое приращение фазы). Теперь
разбор строгий (`strtod`/`strtol`) и добавлена проверка: `carrier − deviation
> 1 Гц`, `carrier + deviation < 4000 Гц` (Наквист), частоты тонов в допустимом
диапазоне, порог 0..255, `lpm` совместим с частотой дискретизации; выход больше
4 GiB отвергается до аллокации.

Проверено: `-c abc`, `-d 2000`, `-c 3900 -d 400`, `-l 0`, `-l 500000`,
`-t 300`, `-p -5`, `-s 5000`, `-l 12x` — exit 1 с сообщением; `-p 0` и вызов
по умолчанию — exit 0.

## Оставшиеся ограничения

- **Связка с реальным радио не проверена.** Все цифры получены офлайн:
  генерация → декодирование → сравнение с исходником.
- **Полностью прозрачные пиксели считаются бумагой (белым).** Проверено на
  RGBA-карте с намеренно прозрачной половиной: 50 % совпадения с тем, что
  даёт PIL, игнорирующий альфу.
- **Изображение целиком буферизуется в памяти** — RGBA (4 байта/пиксель) плюс
  grayscale (1 байт/пиксель); вход ограничен 64 Мпиксель (256 MB).
- **Размер выхода ограничен 4 GiB** — 32-битное поле `data` в WAV.
- **`make test` читает поля заголовка через `od` с native-порядком** —
  рассчитано на x86.
- APT реализован упрощённо: только FM (режим 1A), без AM, без сжатия и без
  алгоритмов синхронизации принимающей стороны.

## Отправная точка: hamfax

Реализация самостоятельная, но отправной точкой служил
[hamfax](https://hamfax.sourceforge.net/) — © 2001, 2011 Christof Schmitt,
DH1CS, GPL-2.0-or-later. Ни одной строки его кода здесь нет: точный поиск всех
строк `tiff2wav.c` длиной ≥ 25 символов по исходникам hamfax и spandsp даёт
только шаблонные совпадения (`int main(int argc, char *argv[])`, идиомы
`TIFFGetField(...)`). Вот что именно послужило примером — по исходникам
`hamfax/src/Config.cpp` и `hamfax/src/FaxTransmitter.cpp`:

| | hamfax | fax-gen |
|---|---|---|
| несущая / отклонение | 1900 / 400 Гц | те же значения по умолчанию |
| строк в минуту | 120 | 120 |
| APT start / stop | 300 Гц / 5 с и 450 Гц / 5 с | те же |
| отсчётов на строку | `60.0*sampleRate/lpm` | та же формула |
| порядок блоков | start → phasing → image → stop | тот же (его задаёт формат APT) |
| старт/стоп тон | `(sampleNr*2*startFreq/sampleRate)%2` | `((i / half_period_samples) & 1u)` — та же идея, другая запись |
| запись звука | Next/.au, 16 бит, **big-endian**, 8000 Гц | WAV little-endian (big-endian от hamfax сюда попал и был исправлен) |
| фазировка | 20 строк, белый при `pos < 0.025 \|\| pos >= 0.975`, плюс отдельная белая строка | по умолчанию WMO: 60 строк, 25 мс белого в начале |
| хвост | отсутствует | 10 с чёрного уровня |
| реализация | C++/Qt, конечный автомат, таблица синуса | C99, фазовый аккумулятор 32 бита + `sin()` |

Совпадают значения по умолчанию, порядок блоков формата и одна арифметическая
формула — это параметры открытого формата и способы их вычислить, а не выражение.
Расходящуюся фазировку можно включить пресетом.

### Пресет `--hamfax`

```bash
./tiff2wav --hamfax image.tiff output.wav     # он же -H
```

Воспроизводит поведение hamfax: 20 фазировочных строк, белый уровень, пока
позиция внутри строки `< 2.5 %` или `>= 97.5 %`, одна дополнительная полностью
белая строка после них, без чёрного хвоста. Несущая, отклонение, LPM и тона APT
уже совпадают с дефолтами hamfax, поэтому пресет меняет только фазировку и
хвост. Опции, указанные после `--hamfax`, перекрывают пресет
(`--hamfax -p 30` → 30 строк).

Проверено измерением сгенерированного сигнала (all-black карта, частота по
нулевым пересечениям в окнах по 50 отсчётов, первая строка фазировки):

| Режим | начало строки | середина | конец строки |
|---|---|---|---|
| `--hamfax` | `[50:100] = 2320 Гц` | `[100:150] = 1520 Гц` | `[3900:3950] = 2320 Гц` |
| по умолчанию | `[50:100] = 2320 Гц` | `[200:250] = 1520 Гц` | `[3900:3950] = 1520 Гц` |

У пресета белый уровень заканчивается ровно на 100 отсчётах (2.5 % от 4000) и
возвращается на 3900 (97.5 %), а последняя, 21-я строка белая целиком; хвост
отсутствует (последние 5 с — стоп-тон 1900 Гц, тогда как по умолчанию последние
5 с — чёрный уровень 1500 Гц). Длина вывода 1 928 044 байта вместо 2 400 044 —
проверяется в `make test`.
