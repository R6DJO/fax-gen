# tiff2wav — генератор факс-аудио (TIFF → WAV)

Однофайловая консольная утилита на C99: читает TIFF-изображение и пишет
монофонический 16-битный WAV 8 kHz с FM-модуляцией в формате, близком к
**WMO APT** (Automatic Picture Transmission, mode 1A) — формату морских
погодных карт и любительского КВ-факса.

> EN: single-file C99 CLI that turns a TIFF image into 8 kHz mono 16-bit WAV
> audio, FM-modulated in a WMO/APT-like amateur-radio facsimile format.
> MIT licensed, no dependencies except libtiff.

**Статус:** экспериментальная. Работосборка и базовый round-trip проверены
(см. [Тестирование](#тестирование) и [Известные проблемы](#известные-проблемы)).

---

## Зависимости

| Пакет (Debian/Ubuntu) | Зачем |
|---|---|
| `libtiff-dev` | чтение TIFF |
| `build-essential` (`gcc`, `make`) | сборка |
| `libc`, `libm` | стандартные |

WAV пишется вручную (RIFF-заголовок 44 байта), `libsndfile`/`audiofile` не нужны.

## Сборка

```bash
make
```

## Использование

```bash
./tiff2wav [опции] <input.tiff> [output.wav]
```

Если `output.wav` не указан — создаётся `fax_output.wav`.

| Флаг | Описание | По умолчанию |
|------|----------|--------------|
| `-c, --carrier FREQ` | Частота несущей, Гц | 1900 |
| `-d, --deviation DEV` | Частотное отклонение, Гц | 400 |
| `-l, --lpm LPM` | Строк в минуту | 120 |
| `-p, --phasing N` | Количество фазировочных строк | 60 |
| `-s, --start FREQ` | Частота стартового тона, Гц | 300 |
| `-S, --stop FREQ` | Частота стопового тона, Гц | 450 |
| `-t, --threshold N` | Порог бинаризации (0–255) | 128 |
| `-i, --invert` | Инвертировать полярность изображения | — |
| `-h, --help` | Справка | — |

### Примеры режимов

**Морской погодный факс (WMO, значения по умолчанию):**
```bash
./tiff2wav image.tiff output.wav          # carrier 1900 Гц, ±400 Гц, 120 LPM
```

**Меньше фазировки:**
```bash
./tiff2wav -p 20 image.tiff output.wav
```

**Класс A (более узкая полоса):**
```bash
./tiff2wav -c 2400 -d 900 -l 200 -s 1370 -S 1610 image.tiff out.wav
```

## Структура сигнала

1. **APT start tone** — чередование чёрный/белый на `start_freq` Гц, 5 с.
2. **Phasing lines** — `N` строк синхронизации: 25 мс белый уровень + 475 мс чёрный.
3. **Данные изображения** — по одной строке TIFF на строку сигнала;
   чёрный → `carrier − deviation`, белый → `carrier + deviation`.
4. **APT stop tone** — чередование чёрный/белый на `stop_freq` Гц, 5 с.
5. **Black silence** — 10 с чёрного уровня (`carrier − deviation`).

Модуляция: фазовый аккумулятор 32 бита, синус вычисляется на каждом отсчёте
(`sin(2π·phase/2³²)`), частота выбирается из двух приращений (чёрный/белый).

## Тестирование

```bash
make test      # собирает и прогоняет tests/test_card.tiff, проверяет размер WAV
```

`tests/test_card.tiff` — собственная тестовая карта (полосы + шкала серого),
воспроизводится скриптом:

```bash
cd tests && python3 make_test_card.py     # требуется Pillow
```

Round-trip проверялся декодированием сгенерированного WAV по нулевым
пересечениям (собственный декодер, вне репозитория). Совпадение с исходным
изображением при чтении отсчётов **little-endian — так, как их объявляет
заголовок RIFF**: **100 %** для тестовой карты 600×200 и **97.3 %** для
погодной карты 1809×600.

## Известные проблемы

Измерено на этой машине (Ubuntu, libtiff 4.5.1, gcc -O2), а не «по ощущениям»:

1. **Порядок байт в WAV — исправлено в этой ветке.** Отсчёты пишутся
   little-endian, как требует RIFF/PCM. Проверено: частота нулевых пересечений
   в фазировочных строках 3080 Гц (теория — 3080 Гц), round-trip 100 % / 97.3 %
   при чтении файла так, как его объявляет заголовок.
   До исправления данные писались big-endian при заголовке RIFF, и стандартный
   читатель (ffmpeg, audacity, audiofile, воспроизведение через звуковую карту)
   получал 43 % / 52.3 % совпадений и 4960 Гц вместо 3080 Гц. Корректной
   альтернативой было бы объявить формат как `RIFX`, но little-endian
   совместим шире.
2. **TIFF с `BitsPerSample ≠ 8` (в том числе 1-битные bilevel-файлы) читается
   неверно.** Код предполагает 8 бит на канал; для 600×200 bilevel TIFF
   valgrind сообщает 700000 использований неинициализированной памяти,
   round-trip совпадение — 44 %.
3. **Нецелое число отсчётов на строку** (например `-l 110`) даёт расхождение
   между округлением длины строки и длиной буфера: в конце строки остаются
   короткие вставки нулей.

Пункт 1 исправлен в этой ветке; пункты 2 и 3 на момент публикации не исправлены.
